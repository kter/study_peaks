# 学習の可視化と自己管理に関する類似アプリ調査

調査日: 2026-11-19

Study Peaksでは、自習室で計測した時間をそのまま記録し、退室後に今日の成果を確認できる体験を優先したい。比較したアプリからは、時間の集計、学習した日数、目標との差、努力が残る見た目を分けて考える材料が得られた。以下の機能比較は一次情報で確認した事実で、後半の提案はStudy Peaksへの適用を考えた判断である。

## 調査範囲

2026-11-19時点の公式サイト、公式活用ガイド、開発元によるストア説明を確認した。アプリのインストールや実機での操作検証は行っていない。未確認の項目は、公開説明だけでは仕様を判断できなかった項目を指す。料金、OSごとの差、集計時のタイムゾーンや日付境界は比較対象に含めていない。

## Study Peaksへの提案

以下は調査を踏まえた設計上の提案であり、継続率が改善することを実証した結果ではない。

最初の実装では既存の学習履歴画面を拡張し、退室時にも短い結果表示を加える。着席前の入力を増やさず、勉強を終えた時点で記録が残ったことを確認できる構成を勧める。退室サマリーはStudy Peaksの自習室の流れに合わせた独自の提案である。

| 優先度 | 提案 | 参考にする点 |
| --- | --- | --- |
| 最初に | 退室後に今回の学習時間、今日の合計、今週の合計を表示 | Forestの努力を残す発想を、自習室の退室操作に合わせる |
| 最初に | 今日/今週/累計の時間と、週/月の切り替え付きグラフ | 各アプリの期間別集計。既存の7日グラフを拡張する |
| 最初に | 月間カレンダーに学習時間の濃淡を表示し、学習した日数も併記 | YPTの濃淡と、Studyplusの記録日数を組み合わせる |
| 次に | 任意の週間目標を設定し、合計時間と達成率を表示 | Studyplusの週間目標。設定変更不可の仕様まで模倣する必要はない |
| 利用状況を見て判断 | 科目タグ、学習後の一言メモ、累計時間の節目表示 | 科目配分の振り返りと、努力を残す見た目 |

カレンダーは学習した日に色を付け、目標未達の日にも記録を残す。連続日数だけを中心にすると休んだ日に数値が途切れるため、今月の学習日数も見せたい。色の濃さは時間を示すものとし、目標の達成/未達とは表示を分ける。

目標は未設定でも記録画面を使える形にする。まず週間目標を用意し、日次目標は利用者の要望を見て判断する。進行中の週は目標を変更できる設計を勧める。終了した週の目標値は当時の値を保存し、後から目標を変更しても過去の達成状況を振り返れるようにする。

科目やタスクの必須入力、ランキング、収集ゲーム、外部カレンダー同期は初期範囲に含めない。Study Peaksの仕様が定める、他者の存在を感じながら自分の学習に集中する体験に合わせ、記録を増やすための操作を抑える。[アプリ仕様](../../specification.txt)

学習時間は取り組んだ量として表示し、理解度や学力の伸びを表す指標とは区別する。成果の中身を振り返る必要が出た段階で、一言メモなどを検討する。

## 実装前に決めること

現在のコードでは退室時に端末内のSQLiteへ学習セッションを保存し、開始日へ時間をまとめて集計する。日付をまたぐ時間の配分、学習中の時間の表示、アカウントごとの履歴分離、強制終了時の保持、端末変更時の引き継ぎを決める必要がある。[記録処理](../../lib/providers/session_provider.dart) / [集計処理](../../lib/repositories/study_history_repository.dart)

実装後は退室後に自分の記録を見た割合や、翌週も学習した割合を確認すると、提案が継続につながったかを判断する材料になる。数値目標は現時点では置かない。
